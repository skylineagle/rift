This manual explains how Rift is built. It is for people who change Rift or embed `rift-core`. If you only want to use Rift, read the user manual.

Rift joins two endpoints, side A and side B, and moves bytes both ways. One Rust library, `rift-core`, does all of that work. The CLI, the desktop app and the container image are thin hosts around it.

The root `Cargo.toml` is a workspace with three members: `crates/rift-core`, `crates/rift-cli` and `apps/desktop/src-tauri`. All three share one version, set in `[workspace.package]`. `bench/` has its own `[workspace]` table, so it is not part of the main build.

| Path | Package | Role |
| --- | --- | --- |
| `crates/rift-core` | `rift-bridge-core` (lib name `rift_core`) | Engine, profiles, payloads, workflows, control socket, logging |
| `crates/rift-cli` | `rift-cli` (binary `rift`) | Command line host |
| `apps/desktop/src-tauri` | `rift-desktop` (lib `rift_desktop_lib`) | Tauri backend that hosts the engine |
| `apps/desktop/src` | `rift-desktop` (npm) | React frontend |
| `bench` | `rift-bench` | Throughput, CPU and memory benchmarks against a built `rift` binary |

The workspace dependency table renames the core package so other crates write `rift-core` in their manifests and `rift_core` in code:

```toml
rift-core = { package = "rift-bridge-core", path = "crates/rift-core", version = "0.2.1" }
```
